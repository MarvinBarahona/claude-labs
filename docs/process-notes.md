Append-only log of suggestions the drafting/build process can't apply itself: coding-convention/process changes, and changes to files it doesn't own (`README.md`, `CLAUDE.md`, other skills). Written during planning or graduation, never applied automatically. Reviewed and cleared manually, on your own schedule.

- **`frontend/tsconfig.json`** — TypeScript `strict` mode (and Angular's `strictTemplates`) isn't enabled; only four piecemeal flags (`noImplicitOverride`, `noPropertyAccessFromIndexSignature`, `noImplicitReturns`, `noFallthroughCasesInSwitch`) are set, none of which cover `strictNullChecks`, `noImplicitAny`, or `strictPropertyInitialization`. The frontend is already written as if strict were on (readonly everywhere, `unknown` + manual runtime narrowing, explicit `| null` unions), so turning it on would likely need few or no code changes — but it's a repo-wide config edit outside any single lab's build scope, worth doing as its own deliberate compile-and-fix pass rather than folded into an unrelated feature's work. Found during a full frontend code review; not caught by any existing test, since `npm test`'s type-checking is separate from this config gap.
